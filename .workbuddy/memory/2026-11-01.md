# 2026-11-01

## QuadDock 代码通读与评审

- 项目性质：.NET 8 WinForms 桌面小工具（约 2825 行 C#），用 AppBar API 把显示器四边变成真实占位的侧栏，中间工作区被系统挤压。
- 结构：`Program.cs`（单实例 mutex + 命名事件唤醒）、`Core/DockManager.cs`（900 行总控，布局协商/托盘/热键/定时扫描）、`Core/AppBarSlot.cs`（ABM_NEW/SETPOS/REMOVE）、`Core/VirtualDesktops.cs`（ImmersiveShell 私有 COM）、`Core/DesktopWindowScanner.cs`、`UI/StripForm.cs`（自绘侧栏）、`UI/Theme|Painter|Dpi.cs`。
- 核心设计：风车式拼法（上→左上、右→右上、下→右下、左→左下），四角各归一条边，避免角落留缺口；只在**结构变化**时摘掉全部 AppBar 重新协商，纯粗细变化走 SETPOS 直排，规避自激的 WM_SETTINGCHANGE 循环。
- 已识别问题（未修改）：
  1. 本机只装了 .NET SDK 3.1，`dotnet build` 无法编译 net8.0 目标；需装 SDK 8。
  2. `VirtualDesktops.GetDesktopAt` 返回的 IVirtualDesktop 未 `Marshal.ReleaseComObject`，每次切桌面泄漏一个 RCW。
  3. `DesktopWindowScanner` 未过滤 DWMWA_CLOAKED，UWP 应用（ApplicationFrameWindow）会出现重复/幽灵条目。
  4. 主题不跟随系统：`WM_SETTINGCHANGE` 只触发重排，未监听 `ImmersiveColorSet`。
  5. 1.2s 窗口扫描（EnumWindows + 大量 COM）跑在 UI 线程，窗口多时可能卡顿。
  6. `ActivateWindow` 切桌面后立即 SetForegroundWindow，切换动画未完成时可能激活失败。
  7. 无开机自启、无 .ico、无 README、非 git 仓库、dist 单文件 71MB。
- 工程状态：`%APPDATA%/QuadDock/settings.json` 四边粗细均为最小值（64/56），`error.log` 为空，进程正在运行。

## 回归修复：cloaked 过滤把别的桌面的窗口全吃了

- 症状：只有当前桌面对应的那条边有窗口，其他三条全空。
- 根因：**虚拟桌面就是用 DWM 遮蔽实现的**，不在当前桌面的窗口一律 `DWMWA_CLOAKED != 0`。上一轮无差别过滤 cloaked，等于把所有跨桌面窗口都滤掉了。
- 修法：`DesktopWindowScanner.Scan` 先算 `currentIndex = ids.IndexOf(GetCurrentDesktopId())`，只在 `desktopIndex == currentIndex` 时才用 IsCloaked 判定为幽灵窗口。
- 顺带补 UX：侧栏没有窗口时居中画一个灰色「桌面 N」，说明这条边绑的是哪个桌面（`StripForm.SetHint` + `StripForm.DrawEmptyHint` + `Theme.EmptyHint`）。
- 验证手段：PowerShell 截屏（`CopyFromScreen`）→ 黑掉中间区域 → 只留四条边 → 肉眼/视觉模型确认 chip 数量。注意侧栏提示是垂直居中的，只截顶部看不到。
- 发布后确认：四条边都有 chip，`error.log` 为空。

### 调试手法（本环境实测有效）
- **截屏核对**：`CopyFromScreen` → 把中间和任务栏涂黑 → 只留四边，再按区域放大 3x 存 PNG，用视觉模型读。像素级核对用 `GetPixel` 竖直/横向扫描找卡片边界。
- **点击**：`mouse_event` 注入在本环境**无效**（不报错但应用收不到），改用 `WindowFromPoint` + `PostMessage(WM_LBUTTONDOWN/UP, MAKELPARAM(client))`，可以真实触发交换。
- **悬停**：必须先 `SetCursorPos` 把真实光标移到目标上，**再** PostMessage `WM_MOUSEMOVE`。否则 WinForms 的 `TrackMouseEvent` 判定光标不在窗口内，立刻补发 `WM_MOUSELEAVE` 把 hover 清掉；抓图稍慢就什么都没了。
- **编译前必须先退出进程**：`bin\Release\...\QuadDock.exe` 被占用会报 MSB3027/MSB3021。

## 修正：书脊宽度不跟随侧栏宽度（提交 f9dce85）

- 症状：用户把左侧栏拖到 103px，标签宽度没变，只是从 2 列变成 3 列。
- 根因：`columns = (usable + gap) / (minSpine + gap)` 让列数吃掉了所有新增宽度，`spineWidth` 永远卡在 22–26px。
- 修法：**列数固定为 2**（可用宽度不够两列时才 1 列），`spineWidth = (usable - gap) / 2`，上限 48px；超上限后 `block` 居中留白。
- 配套：书脊字号从 9pt 按 `spineWidth/23` 放大（上限 1.5 倍），图标 `min(22, max(13, w*2/3))`；都用 `_spineFont`/`_spineIcon` 字段，在 `UpdateSpineMetrics` 里随宽度重建。`Measure` → `MeasureSpine` 保证高度按同一个字号算。
- 教训：任何"自适应列数"的网格，只要格子宽度不随容器变化，用户拖动容器就会觉得没反应。

## 再修正：两列留空 → 单列铺满（提交 09a079a）

- 症状：拖到 112px 后，一个窗口只占左边一列 42px，右边整列空着 → "标签只占了侧栏一半"。
- 根因：两列布局只在**有足够窗口**时才成立；窗口少的时候空列就是纯浪费。
- 修法：`columns = 1`，`spineWidth = width - 2*pad`，铺满整条边；单条高度上限放到整条边（`height - 2*pad`），溢出靠滚动。
- 字号：`9pt * sqrt(spineWidth/23)`，**上限 15pt**。线性放大会让宽侧栏的标题大到夸张；上限 15pt 是因为再大长标题在一条边上就放不下、只剩省略号（一条边的可视高度只有 ~976px）。
- 图标同步按 sqrt 放大，上限 30px。
- 注意：用户此时已自行切到 **深色 + 列表风格**，宽度 112px —— 改动都要在"深色列表"下也看一遍。
