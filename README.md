# QuadDock · 四边侧栏

把屏幕的上下左右四条边变成常驻侧栏，并且**真实占位**——不再是一层浮在窗口上的遮罩，而是向系统注册 AppBar，让 `rcWork` 真的变小。最大化窗口只会在中间那块区域里铺开，不会盖住侧栏。

一共 5 个虚拟桌面：中央一个，四条边各压一个。**点哪条边，就把中央的桌面和它交换**——像四个卡槽，把想用的那张抽到中间。

## 用起来

| 操作 | 效果 |
| --- | --- |
| 点侧栏空白 | 把这条边压着的桌面和中央**交换** |
| 点窗口标题 | 先把它所在的桌面换到中央，再激活那个窗口 |
| 拖内边缘 | 调这条边的宽窄（左右 64–520 px，上下 56–400 px） |
| 双击内边缘 | 复位成默认宽度 |
| 滚轮 | 标题多到放不下时滚动列表 |
| 右键侧栏 / 托盘图标 | 打开菜单：开关每条边、桌面对应一览、预设宽度、主题、停靠显示器、开机启动 |
| `Ctrl + Alt + Space` | 隐藏 / 显示全部侧栏（不进任务栏，随时按回来） |

再次启动程序不会开第二个进程，而是把已有实例的侧栏叫出来。

每条侧栏显示的是**它此刻压着的那个桌面**上的窗口，不管你现在在哪个桌面。所以一条边空着是正常的——那个桌面没开窗口而已，空白处会写出「桌面 N」。交换之后两侧的列表会立刻对调。

如果桌面不足 5 个，启动时会自动补齐（只新建，不删除）。

## 配置文件

`%APPDATA%\QuadDock\settings.json`，改完重启生效。粗细都以 96 DPI 的逻辑像素记录，实际渲染时按目标显示器的 DPI 缩放。

`Slots` 是五个槽位各自压着列表里的第几个桌面，顺序固定为 **中央、左、上、右、下**，必须是 `1..5` 的一个排列。每次交换都会自动写回，所以下次启动还是你摆好的样子。

出错信息写到同目录的 `error.log`。

## 编译

需要 **.NET 8 SDK**（本项目在 8.0.427 上验证）。注意本机 SDK 装在 `D:\software\dotnet8`，不在 PATH 里，直接敲 `dotnet` 会用到系统自带的 3.1：

```bash
D:/software/dotnet8/dotnet.exe build -c Release
```

发布成单文件（自包含，约 70 MB）：

```bash
D:/software/dotnet8/dotnet.exe publish -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true
```

如果目标机器装了 .NET 8 桌面运行时，去掉 `--self-contained true` 可以把体积压到 1–2 MB。

## 实现要点

- **风车式拼法**：上边独占左上角、右边右上角、下边右下角、左边左下角。AppBar 有个隐式约束——横边一旦占位，竖边就只能落在两条横边之间，四角很容易漏出桌面。让每个角只归一条边独占，并且窗口位置用自己算的矩形（不用 `ABM_SETPOS` 回填的 `rc`，那个值会被外壳裁掉角段）就能避开。
- **只在结构变化时重新协商**：首次布局、开关某条边、换屏、DPI 变化时才把四条 AppBar 全部摘掉重排；单纯调粗细时矩形已经算好，直接 `SETPOS`。
- **防自激**：`ABM_SETPOS` 会让外壳广播 `WM_SETTINGCHANGE`。如果收到广播就重排，会形成「排布 → 广播 → 再排布」的死循环，表现为最大化窗口反复被推动。代码里用「当前 `rcWork` 是否等于自己推算的预期值」来识别并忽略自己引起的广播。
- **槽位用 GUID 不用序号**：桌面可以被重排、被删，序号会漂。槽位里存的是桌面 GUID，只有落盘时才换算成序号。
- **外部切桌面也收敛**：你在任务视图里自己切到某个被侧栏压着的桌面时，它会被自动换到中央、原来的中央退到那条边——和点侧栏是同一个语义，模型不会跑偏。
- **等落定再动**：桌面切换是异步的，`SwitchDesktop` 返回时前台和当前桌面都还没变。用 160ms 定时器轮询「当前桌面 == 中央槽」再搬侧栏、激活窗口，最多重试约 1 秒。

## 已知限制

- 虚拟桌面用的是 Explorer 的 `ImmersiveShell` 私有 COM 接口，没有公开 API。接口布局对 Windows 版本敏感，系统大版本更新后可能失效——失效时虚拟桌面相关功能整体禁用，侧栏本身不受影响。
- 提权窗口（以管理员身份运行的程序）拿不到所属桌面 ID，不会出现在列表里。
- 只能停靠一台显示器。
